You are matching the fields of one kind of record (LEFT) with the fields of
another kind of record (RIGHT). Decide which LEFT fields describe the same
property as which RIGHT fields. You do not convert values. You only decide which
fields correspond.

**INPUT**

[LEFT]
One or more left samples, separated by `---EXAMPLE SEPARATOR---`. Each sample
contains:

- [OBJECT]: the record as a JSON object mapping field names to string values.
- [SOURCE DOCUMENT]: the document the record was extracted from. Content between
  `<!-- TARGET_START -->` and `<!-- TARGET_END -->` marks the location the record
  was extracted from. The markers are not data, and anything outside them is
  still context.

[RIGHT]
One or more right samples, separated by `---EXAMPLE SEPARATOR---`, in the same
form as [LEFT].

Keys repeat across samples while values vary. The samples are a sample of each
side, not a complete schema.

Field names are hints, not proof. Confirm what a field means from its values,
types, formats, ranges, and the context in the source document.

**THE GOAL**

Return every pair of one LEFT field and one RIGHT field that describe the same
property of the same kind of entity. Return only pairs you can defend. Returning
no pairs is a valid answer.

**HOW TO MATCH**

Two fields match when:

- They describe the same property of the same kind of entity. A shared topic is
  not enough. Two fields about the same entity do not match unless they carry the
  same property.
- The values of one are a representation of the values of the other. Surface
  differences such as units, labels, wrappers, abbreviation, casing, or encoding
  do not rule out a match.
- A single general rule could turn the left values into the right form, without
  an external lookup and without guessing individual values.

Consider:

- Meaning, from the field name, the values, and the source document's context.
- Data type, format, and structure.
- Units, prefixes, suffixes, and labels.
- Whether a value is relative, abbreviated, or encoded, and whether the source
  document establishes what it is relative to.
- Plausible value ranges.

Rules:

- Each LEFT field appears in at most one pair, and each RIGHT field appears in at
  most one pair.
- When several fields could match, pair the closest one and leave the rest
  unpaired.
- Do not match fields because their primitive types agree, or because of their
  position in the record.
- Do not match a field that holds a different property of the same entity.
- Do not match a field when the correspondence depends on information the input
  does not provide.
- Use field names exactly as they appear in the samples.

**RESPONSE FORMAT**

Respond with valid JSON only. Do not include Markdown, code fences, comments, or
text outside the JSON. Use exactly this structure:

{
  "matches": [
    { "left_field": "<a key from [LEFT]>", "right_field": "<a key from [RIGHT]>" }
  ]
}

- `left_field` must be copied exactly from a key in the [LEFT] objects.
- `right_field` must be copied exactly from a key in the [RIGHT] objects.
- If no fields match, return:

{
  "matches": []
}
