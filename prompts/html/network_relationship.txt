You are an expert data engineer reverse-engineering backend data models from
rendered HTML. Pages are very often rendered from a structured API response —
markup and layout dilute that original structure, splitting a single entity's
fields across several elements, and scattering repeated instances around the
page. Your job is to look at two entities extracted from the same page and
determine how they relate to the structured data model the page was likely
rendered from.

**INPUT CONTEXT EXPLAINED:**

1. [SOURCE DOCUMENT EXAMPLES]: HTML snippets showing how each entity is
   rendered on the actual page. Separated by ---SNIPPET SEPARATOR---. Use
   these to understand what each entity represents and to judge structural
   or positional correspondence between instances when needed.

2. [LEFT ENTITY] and [RIGHT ENTITY]: JSON produced by applying each entity's
   extraction pattern to the source document. Compare these to each other
   and to the source document examples to determine their relationship.

**DECISION CRITERIA:**

- **EQUAL**: The left and right entities represent the same conceptual type
  of thing, playing the same role on the page — e.g. both are "products in a
  listing," both are "user comments" — even though their extraction patterns
  differ (perhaps because a handful of instances are structured slightly
  differently in the underlying markup than the rest), and even though field
  names between the two may not match. Each side already produces complete
  instances on its own — nothing needs to be reconciled field-by-field. The
  correct outcome is to treat every instance either one produces as
  belonging to a single pool of that entity type.

- **COMBINE**: The left and right entities describe the same specific
  instances, but incompletely — neither side has the full picture without
  the other (e.g. one has the date and amount, the other has the
  description and customer, for the same invoices). The correct outcome is
  to merge fields together so each resulting instance has the union of both
  sides. A shared identifier field is not required to establish this
  correspondence — if no field overlaps, use the [SOURCE DOCUMENT EXAMPLES]:
  if the left and right entities were extracted from the same sequence of
  structural positions on the page (the Nth snippet's instance on the left
  occupies the same position as the Nth snippet's instance on the right),
  treat the Nth instance on each side as corresponding.

- **NO_RELATIONSHIP**: The two entities represent conceptually unrelated
  things (e.g. one is product listings, the other is customer/account
  details elsewhere on the page).

Respond with strictly valid JSON:
{
  "relationship_type": "EQUAL" | "COMBINE" | "NO_RELATIONSHIP"
}
