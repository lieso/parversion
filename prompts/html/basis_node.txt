**NORMALIZATION:**

Raw values of the same field vary in representation across occurrences: stray
whitespace, units and labels, wrappers, inconsistent casing, mixed date or number
formats, entity encoding, and so on. For each meaningful field, write a Scheme
program that converts any raw value of that field into one canonical form, so
that equivalent values become identical.

Decide the canonical form from what the field is: its role, its values across
all occurrences, and its context in the document. Use the conventional
representation for that kind of value. For example:

- numbers (prices, counts, ratings): plain decimal digits with an optional
  leading `-` and a `.` decimal point, with no thousands separators, currency
  symbols, or units
- dates and times: ISO 8601 (`YYYY-MM-DD` or `YYYY-MM-DDTHH:MM:SS`), keeping
  only the precision the value actually has
- booleans: exactly `true` or `false`
- URLs: the URL with surrounding whitespace removed
- free text and names: surrounding whitespace removed and internal whitespace
  runs collapsed to a single space

The program is a single Scheme lambda expression with one argument, `value`:

(lambda (value) ...)

`value` is the raw source value as a string. The result must be a string.

Language and safety requirements:

- Write R7RS-small Scheme. Use only R7RS-small procedures and special forms.
- The program must be pure and deterministic.
- Do not perform input or output.
- Do not access the network, file system, environment, or current time.
- Do not use randomness, `eval`, or `load`.
- Do not mutate state outside the program's own local bindings.
- Recursion and iteration must be bounded by the length of `value`.

Program rules:

- Generalize beyond the samples. Encode a rule that works for values not yet
  seen, not one that fits only the occurrences shown.
- Do not compare against, branch on, embed, or return individual sampled values.
  Do not build a lookup table from the samples.
- Do not invent missing information. If making a value canonical would need data
  the input does not provide (an external lookup, the current date, a base URL
  that is not shown), do not attempt it. Normalize only what the value itself
  determines.
- Remove representational noise (units, labels, wrappers, redundant
  representation) only when the result is the canonical form of the value.
  Preserve all information the field carries.
- Values that mean the same thing must produce the same output. Values that mean
  different things must produce different outputs.
- If values already have a consistent canonical form, the identity program
  `(lambda (value) value)` is the correct program. Do not add transformations
  for the sake of it.
- A value that cannot be normalized should pass through unchanged rather than
  being dropped or guessed.
- Mentally test the program against every sampled value and check that the
  results are consistent with each other and appropriate for the field.
