You are analyzing HTML content to extract the underlying business data model
from a rendered webpage.

**THE GOAL:** Reconstruct what structured data the backend provided. When a
page renders a product listing, it came from something like:
  [{id: 123, name: "Widget", price: 19.99, image_url: "...", ...}]

We want to extract that structure, filtering out everything else: UI chrome,
framework artifacts, presentation noise, and advertisements.

**HOW TO READ THE CONTEXT INSTANCES:**
Multiple context instances are provided below (separated by ---OCCURRENCE SEPARATOR---).
Each instance shows:
1. SPATIAL CONTEXT: A zoomed-in HTML fragment centered on the field location,
   showing immediate siblings and parent relationships. This reveals the actual
   content and structural position.
2. POSITIONAL CONTEXT: The complete path from document root to the target node
   (e.g., "html/body/table/tbody/tr/td/a[@href]"). This shows the full structural lineage.
3. EXTRACTED FIELDS: The field name and value that have been identified at this location.

Use all three perspectives together to understand the field's semantic role and whether
it represents meaningful application data.

**EVALUATION TASK:**
For each EXTRACTED FIELD shown, evaluate independently whether it represents
application data or boilerplate/noise. When multiple instances are provided
(separated by ---OCCURRENCE SEPARATOR---), assess whether the field consistently
represents meaningful data across occurrences. If instances are mixed (some boilerplate,
some not), describe the dominant semantic role.

**ELIMINATION CRITERIA (do not include in response):**

1. **Advertisements & Promotional Content:** Sponsored products, promo banners,
   upsell text, affiliate links, promotional URLs, tracking pixels, ad network
   attributes. Anything designed for marketing rather than the core product/content.

   EXAMPLES - BOILERPLATE:
   - FIELD=href: Links to external vendor promotions or signup pages
   - TEXT: "Limited time offer!" (marketing copy)

2. **Framework & Code Artifacts:** Data attributes, configuration
   objects, base64-encoded data, event handlers (onclick, onload, etc.),
   framework-specific attributes.

3. **UI Structure & Styling:** Punctuation (|, •, →), UI affordances
   (button labels like "Search", "Submit", "Add to Cart"), CSS classes, inline
   styles, IDs, ARIA labels that act as layout markers. Action links that trigger
   UI state changes (e.g., "hide", "upvote", "delete", "reply") are boilerplate,
   EVEN IF their URLs contain valid entity IDs.

   EXAMPLES - BOILERPLATE:
   - TEXT: "Submit", "Search", "Next page" (button labels)
   - TEXT: "|", "•", "→" (separators)
   - FIELD=href: "?sort=desc", "hide?id=123", "reply?id=123" (UI actions/affordances)

4. **Hardcoded Static Content:** Version numbers, "All rights
   reserved", disclaimer text, navigation links to static pages, social media
   follow buttons (unless the page is those profiles).

   EXAMPLES - BOILERPLATE:
   - TEXT: "© 2024 Company Inc.", "Privacy Policy", "Terms of Service"
   - FIELD=href: Generic contact/help pages

5. **Empty or Placeholder Content:** Empty text, loading states, placeholder text.

**INCLUSION CRITERIA (include in response):**
A field is meaningful if it would be stored in the backend's API response data.
Ask: "Would a backend engineer include this specific field in the database or JSON response?"

EXAMPLES - MEANINGFUL:
- FIELD=href: Product URLs, article links, user profile links that vary
  per item shown on the page
- TEXT: Product name, price, description, publication date, author name, or
  user-generated content that changes per item.

For meaningful fields, provide exactly one mapping per source field:
- source_field: The original field from the extracted fields (e.g., "TEXT", "FIELD=href")
- field_name: Semantic snake_case identifier reflecting its role in the data model
- description: Brief description of what this field represents
- data_type: Inferred primitive type (string, number, boolean, url, datetime, etc.)
- format: Optional. More specific type hint if applicable.

**Important:** Each source field should map to exactly one output field_name. Do not provide multiple mappings for the same source field.

Note on field notation: In EXTRACTED FIELDS, href attributes are shown as "FIELD: href, VALUE: ..." and text nodes as "FIELD: text, VALUE: ...".

When reporting `source_field` in your response, copy ONLY the field name token that follows "FIELD:" — do not include the "FIELD:" prefix, the "VALUE: ..." portion, or any surrounding punctuation. For example, given "FIELD: href, VALUE: /page", report source_field as exactly "href". For the text node's own content, report source_field as exactly "text".
